**Title**:
Phase 2: Compiled CLI binary (`code-wrapper exec`)

**Description**:
Build the standalone `code-wrapper exec` binary that owns all coding-agent protocol logic (CLI spawning for Claude and Copilot, stream-json/ACP parsing, session lifecycle, stale-session recovery, retry/watchdog handling) and exposes it as a single NDJSON stream on stdout, with no Node.js runtime required on the invoking host. This is the core interface-inversion deliverable — every existing protocol behavior must be reachable through this binary with zero reimplementation.

## Requirements
- New `src/cli/exec.ts` entry point wires `CliProcess`, `SessionManager`, and `runWithRecovery()` directly — no protocol logic is duplicated\n- Binary accepts prompt/input (stdin or `--prompt`), backend selection (`claude`/`copilot`), session ID for resume, `--is-first-message`, idle/max timeout flags, `--skip-permissions`, `--agent`, `--mcp-config`, `--session-dir`, `--recover-stale-session`\n- Emits one NDJSON line per `ClaudeEvent` on stdout, each line including the `v` wire-protocol version field from Phase 1's schema\n- Manages its own process group (`setsid` equivalent) so a SIGKILL to the binary does not orphan the underlying `claude`/`copilot` child process; forwards SIGTERM to the group\n- Exits with structured exit codes (0 clean, 1 CLI error, 2 binary-level failure, 3 wire protocol error)\n- Compiles to standalone binaries for linux-x64, linux-arm64, darwin-x64, darwin-arm64 via `bun build --compile`\n- Supports both the Claude backend and the Copilot ACP backend (JSON-RPC handshake, session UUID lifecycle, tool_call correlation, dual-done-signal handling) through the same output contract\n- GitHub Actions release workflow compiles and attaches all four platform binaries on version tag\n- Contract tests spawn the compiled binary against existing fixtures (`fake-claude.mjs`, `fake-copilot.mjs`) and validate every emitted line against the Phase 1 JSON Schema

## Design Guidance
Implements the "NEW: src/cli/exec.ts", "Wire Protocol: NDJSON on stdout", "Process Group Management", and Phase 2 of the Implementation Plan sections of the architecture design. Reuses `CliProcess.run()`, `parseCliLine()`/`createCopilotAcpParser()`, `SessionManager`/`FileStore`, and `runWithRecovery()` unchanged per the Component Reuse section.

## Acceptance Criteria
- [ ] Binary runs standalone with no Node.js runtime present on the host\n- [ ] Every emitted stdout line validates against `schemas/claude-event.v1.schema.json`\n- [ ] Both Claude and Copilot backends produce the same typed `ready`/`tool_use`/`tool_result`/`done` event sequence shape through the same binary interface\n- [ ] SIGKILL to the binary does not leave the underlying CLI process running (verified by test)\n- [ ] Structured exit codes (0/1/2/3) match documented behavior\n- [ ] CI contract tests pass against `fake-claude.mjs`/`fake-copilot.mjs` fixtures\n- [ ] Platform binaries for linux-x64, linux-arm64, darwin-x64, darwin-arm64 are produced by the release workflow\n- [ ] Code is reviewed and approved
