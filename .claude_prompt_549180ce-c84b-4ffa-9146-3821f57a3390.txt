[PR Feedback] CLI Binary — Argument Parsing & Process Safety

**Description**:
Based on consolidated PR review, address the following in **CLI Binary — Argument Parsing & Process Safety**:

- **Unknown CLI arguments silently ignored**: In `src/cli/exec.ts:65-123`, the `parseArgs` switch statement has no `default` case. Any misspelled or unrecognized argument (e.g., `--idle_timeout` instead of `--idle-timeout`) is silently dropped and the default value is used. Fix: add a `default` case that emits a warning to stderr or throws for unrecognized flags.
- **Process-group SIGKILL safety not achieved (Req 7 / Story 7)**: The BA doc requires that if the binary is hard-killed (SIGKILL), grandchild CLI processes are also terminated. The implementation spawns children with `detached: true` in a separate process group (`src/process/CliProcess.ts`), so SIGKILL to the binary cannot propagate to the child group. No OS-level mechanism (pdeathsig, subreaper, shared process group) is used, and no test exercises this scenario. This is an explicitly required behavior per the spec.
