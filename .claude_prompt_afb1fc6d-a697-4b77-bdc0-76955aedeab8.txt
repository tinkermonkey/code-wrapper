**Title**:
[PR Feedback] Compiled Binary — Exit Codes & Signal Handling

**Description**:
Based on consolidated PR review, address the following in **Compiled Binary — Exit Codes & Signal Handling**:

- **Structured Exit Codes Not Implemented**: `exec.ts` unconditionally calls `process.exit(0)` after the event loop — it never inspects whether an ErrorEvent was seen, so exit code 1 is never produced. The outer `main().catch(() => process.exit(2))` is unreachable because the inner try/catch already swallows every exception and calls `process.exit(3)`. The binary only ever exits 0 or 3, making the Python client's `returncode == 2` branch dead code.
- **No Process-Group Management in Binary**: `EXEC_BINARY.md` documents that the binary establishes its own process group via `process.setpgid(0, 0)`, but no such call exists in `exec.ts` or `CliProcess.ts`. The `spawn()` call uses plain `{cwd, stdio, env}` (no `detached: true`), and kill logic targets only the child PID. If the binary is killed externally, grandchild processes are orphaned.
- **`main().catch()` Discards All Error Information**: `exec.ts:184` — `main().catch(() => { process.exit(2); })` throws away the error object, permanently losing diagnostic information.
- **Stdin Read Failure Silently Produces Empty Prompt**: `exec.ts:89` — when `readFileSync(0)` throws, the catch block silently sets `prompt = ''`, causing the binary to run with no user input.
- **Missing NaN Validation in CLI Arg Parser**: `exec.ts:48-61` — `parseInt(args[++i], 10)` does not validate for NaN, and `args[++i]` has no bounds check. `--idle-timeout abc` silently sets timeout to NaN.
